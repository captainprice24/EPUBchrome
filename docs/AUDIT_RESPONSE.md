# Audit review and implementation decisions

Reviewed against the [original audit](AUDIT.md), commit `8295eef`, and the v0.2 source it inspected. The original report is preserved unchanged. This response describes the v0.3 changes, distinguishes recommendations from verified defects, and records what remains open.

## Decision

Prioritize rendering correctness, saved-data safety and legibility before adding formats, AI, subscriptions or ecosystem integrations. Keep TypeScript, React, local IndexedDB and the scriptless book iframe. There is no evidence here that a language rewrite or a backend would solve the reported defects.

## Accepted, deferred to the next reader iteration

These remain useful work, but are not prerequisites for the fixes above:

1. **Benchmark the renderer before expanding it.** Compare the corrected engine with Foliate.js and Readium using the same corpus, annotations, CSP and extension packaging. Assess licensing, maintenance, fixed layout, spreads, RTL, vertical writing, resource lifetime, EPUB CFI and performance. Do not replace the engine without measuring those tradeoffs and proving another locator migration.
2. **Navigation and search:** hash routes and deep links, reuse the existing extension tab, whole-book search with result snippets/next/previous, external-link handoff with a visible destination, footnote popovers and a better active-section TOC. External links remain disabled today.
3. **Annotation workflow:** colors, editable notes, snippets for bookmark labels, Markdown/Obsidian export and portable CFI where supported. Current quote anchors are useful, but do not constitute CFI support.
4. **Reading comfort:** immersive/fullscreen mode, spreads, prefetch with a bounded resource cache, unified shortcuts, mobile sheets and live OS-theme following. First launch may use the OS dark preference; no automatic theme-following setting is claimed.
5. **Library:** bulk/folder import, collections, reading status, complete metadata/refinements, a Continue reading strip and per-book reading preferences. Current metadata is still intentionally shallow. Duplicate detection and backup are in place first.
6. **Drive:** `drive.file` plus Picker, optional permissions in configured builds, one-time 401 token refresh and live-account validation. Keep its existing flow explicitly experimental. Restricted-scope verification and any assessment requirements need checking against the actual distribution and data-handling model.
7. **Maintainability:** split the remaining large App component into views/hooks, add a reviewed hooks/TypeScript lint configuration, unit tests for more parser boundaries, visual baselines and performance budgets. New modules reduce coupling but do not finish this refactor.
8. **Later differentiation:** OCR queues/languages/text layers, quality-controlled PDF profiles/TOC/annotations, TTS, optional local AI and additional document formats. Device support, model licenses and real document quality must be tested before product claims.

## Recommendations modified or not adopted

- **Do not assume every rendering fix corrupts every annotation.** CSS alone usually changes geometry, not the text-node sequence. XHTML recovery or sanitizer changes can change that sequence. Raw offsets are valid within a known renderer; the problem is trusting them across changes without verification. Quotes/context are the migration safeguard, and ambiguous matches require review.
- **Do not make all print warnings non-fatal automatically.** Quietly dropping images or fonts conflicts with the requested export-quality promise. Printing still stops and explains the warning. A future print preview should distinguish cosmetic warnings from missing content and allow an explicit, informed decision to continue. This release does not claim the audit's print-warning issue is fully solved.
- **Keep the English model bundled for now.** Offline OCR from installation is part of Folio's privacy/offline value. Removing variants or moving models to first-use downloads requires browser capability and offline packaging tests; install-size savings alone are insufficient. OCR JS is lazy-loaded, but assets stay bundled.
- **Do not measure every chapter using text-only markup.** Removing images can produce incorrect counts for scans, illustrations and complex layouts. Debounce/cancellation are appropriate now; a lighter counter needs evidence that image dimensions and publisher layout remain equivalent.
- **Do not automatically add a permissive project license.** Choosing source-reuse rights affects the owner's commercial plan. A public GitHub repository does not by itself grant general reuse rights. However, an open-source license is not required merely to distribute proprietary software in the Chrome Web Store; the audit overstates that blocker. No source license has been selected here.
- **Do not treat grades, time estimates or a 12 px threshold as standards evidence.** The concrete contrast, focus, tab and content failures are actionable. WCAG does not impose a universal 12 px minimum, and target-size exceptions exist. Automated checks and three corpus books cannot establish complete accessibility or market-wide EPUB compatibility.
- **Do not add AI, subscriptions, DRM workarounds or a backend in response to this audit.** They do not repair the defects. Protect private local reading first, then validate demand for paid workflows and optional services.

## Remaining release limits

The Chrome-origin runtime and Google sign-in cannot be exercised by this cloud's browser policy. The test server runs the production reader with matching script/worker CSP, and the Pages suite checks the real repository subpath. Manual Windows/macOS Chrome, browser upgrades/storage pressure, screen readers, 200% zoom, true large-file performance, many more publishers, fixed layout, vertical CJK, obfuscated fonts and print fidelity still need testing. The 1 GB EPUB limit is a safety ceiling, not a promise of lag-free processing.

Backups are unencrypted; users must protect downloaded copies. Persistence/unlimited storage reduces automatic eviction risk, but does not protect against clearing data, uninstalling or losing a device. Restore accepts archives below 2 GB (4 GB expanded safety budget); individual-book backup is available for larger libraries. Legacy notes-only exports without hashes can match their original library IDs, but cannot reliably identify a separately re-imported book after its original ID has been lost.
